# Deployment Models

The same LMS application architecture supports SaaS and customer-hosted deployments with configuration/provider adapters rather than separate product forks.

## SaaS baseline

- multi-tenant logical isolation
- Phase 1 single-primary application/database baseline
- automated encrypted backups and tested restore
- externalized artifact repository
- protected signing provider
- health monitoring and alerting
- design remains horizontally/HA evolvable without changing domain model

## Customer-hosted baseline

- same application codebase
- isolated customer deployment
- customer-managed or vendor-approved PostgreSQL/artifact storage/signing integration
- manual signed LMS upgrade package initially
- outbound dependencies minimized and explicitly documented
- HA optional enterprise deployment profile
- customer environment may be disconnected from vendor SaaS

## Edge connectivity modes

1. **Online** — device communicates directly with LMS.
2. **Assisted offline** — authorized relay transports signed request/response data.
3. **Fully air-gapped** — controlled media carries signed request/response packages.

All routes use the same grant/artifact trust model; connectivity mode changes transport, not authorization semantics.

## Deployment dependencies

| Dependency | SaaS | Customer-hosted | Failure effect |
|---|---|---|---|
| PostgreSQL | vendor managed | customer/vendor managed | LMS writes unavailable; no unsigned fallback |
| Artifact storage | object storage | MinIO/approved repository | package delivery unavailable |
| Signing provider | KMS/HSM/equivalent | approved protected provider | new grant/release signing blocked |
| Email | provider | SMTP/relay | notifications delayed only |
| ERP | optional integration | optional integration | reconciliation/commercial import delayed |
| Telemetry store | separate/optional | separate/optional | analytics delayed; licensing unaffected |

## Network exposure principle

Only required interfaces are exposed. Edge local APIs remain local by default. Customer-hosted network/port matrix must be generated by deployment packaging before production release.

## Upgrade principle

Central LMS upgrade and edge product OTA are separate lifecycles. Customer-hosted LMS upgrades are manual package operations initially; edge application/model updates remain managed through LMS release/deployment functions.
