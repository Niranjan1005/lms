# Phase Exit Criteria

Delivery phases are complete only when their defined outputs and evidence are accepted.

## Phase 1 — Trust foundation

Exit: device identity, enrollment, signed grant canonicalization, verifier, anti-replay/rollback tests and signing-key separation demonstrated.

## Phase 2 — Registry & licensing

Exit: customer/site/device topology, entitlement pools, allocations, grants, base/add-on rules, tenant authorization and audit tests pass.

## Phase 3 — Capacity

Exit: inventory schema, workload model, benchmark governance, central assessment, local authoritative check, recommendations and reassessment triggers validated against representative hardware.

## Phase 4 — Marketplace & release management

Exit: catalog, trial/purchase flow, release channels, signed manifests, artifact repository, dependency/compatibility checks and portal states complete.

## Phase 5 — Model OTA & deployment

Exit: encrypted model delivery, model inventory, auto/manual deployment, maintenance windows, release-set health-check/rollback and model-only OTA proven.

## Phase 6 — Lifecycle/offline

Exit: renewal, three clocks, check-in, grace, revocation, rehost, transfer, decommission, online/offline/air-gapped request-response and receipt reconciliation pass end-to-end tests.

## Phase 7 — Hardening

Exit: VAPT disposition, performance/resilience testing, backup restore, DR exercise, operational runbooks, monitoring/alerting, support readiness, ERP reconciliation and production release approval complete.

## Ownership

Each phase has named Product, Engineering, QA and Security/Operations approvers appropriate to the risk. Evidence is linked to issues/PRs/test reports/releases rather than accepted verbally.
